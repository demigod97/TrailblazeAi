## Codebase Patterns (Accumulated Learnings)

<!-- Append patterns discovered during implementation here -->
- PipelineClient structural type avoids generated-type lag (from Stories 2.x)
- `as unknown as PipelineClient` is the established cast pattern — never use `as any`
- pg-boss `send()` for job chaining belongs in queue-handlers.ts, NOT in stage functions
- Supabase `insert()` takes an array, not a single object: `db.from('table').insert([rowObject])`
- YAML prompts loaded at module level (not per-call) for performance — use module-level cache with `_resetPromptCache()` for testing
- `BossWithWork` structural type is already defined in queue-handlers.ts — reuse it
- Queue config examples: `{ retryLimit: 2, retryBackoff: true, expireInHours: 0.5 }` for AI stages
- Queues are created at API startup in `apps/api/src/plugins/pg-boss.ts` (registered via `app.ts`)
- `node-html-parser` is already installed for HTML parsing
- Handler errors: `throw err` makes pg-boss retry; `return` prevents retries
- ChonkieJS (`@chonkiejs/core`) does NOT support chunk overlap natively — implement manual overlap in calling code
- `String.prototype.replace` callback provides `offset` as second arg (after match) — use it instead of `indexOf` for duplicate-safe position lookups
- Always use Zod `safeParse` at system boundaries for JSONB data written by LLM calls — never trust `as` cast
- `conceptExtractionSchema` from `knowledge-agent.ts` is the canonical Zod schema for sf_concepts validation
- Guard against empty chunk arrays before calling `supabase.insert()` — some clients reject empty inserts
