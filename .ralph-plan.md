## Architecture Context Summary

1. **Hybrid Deployment (Decision 1):** Three-tier architecture — Vercel (Next.js 15 frontend), Hetzner VPS CX33 (Fastify API + Worker + Nginx in Docker), Supabase (PostgreSQL + pgvector + Realtime + Auth). VPS writes status to Supabase, frontend receives via Realtime WebSocket. No SSE through Vercel.
2. **API Patterns (Decisions 7/9):** Fastify 5 with ApiResponse envelope (`ApiSuccess<T> | ApiError`), AppError hierarchy (NotFoundError, ValidationError, PipelineError), Bearer token auth, snake_case JSON matching database columns, Zod validation at all system boundaries.
3. **Database Patterns (Decision 12):** Supabase CLI migrations (7 sequential), pgvector with HNSW indexing (m=16, ef_construction=64), hybrid_search() SQL function with RRF re-ranking (full_text_weight=1.5, semantic_weight=1.0), snake_case everywhere, RLS policies on all tables.
4. **Browser Automation (Decision 2):** Playwright MCP (stdio transport) as primary — accessibility tree snapshots, persistent browser profiles in Docker volume. Stagehand v3 fallback for Shadow DOM extraction failures with Zod schema validation.
5. **Job Queue (Decision 8):** pg-boss v10 with queue-per-stage pattern — 7 named queues with stage-specific retry config, concurrency limits (scrape: 2, embeddings: 5, quiz: 3), dead letter queues, priority ordering (quiz-ready=1), pause/resume per queue.
