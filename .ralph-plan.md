## Architecture Context Summary

**Deployment**: Three-tier hybrid — Vercel (Next.js frontend), Hetzner CX33 VPS (Fastify API + Worker in Docker), Supabase (PostgreSQL + pgvector + Realtime).

**API Patterns**: Fastify 5 with ApiResponse envelope (ApiSuccess<T> | ApiError), AppError hierarchy (NotFoundError, ValidationError, PipelineError), global error handler, Bearer token auth on all non-health endpoints, snake_case JSON fields matching database.

**Database**: Supabase PostgreSQL with pgvector extension, HNSW indexing (m=16, ef_construction=64), 7 sequential migrations, Row-Level Security, connection pooling for concurrent operations.

**Browser Automation**: Playwright MCP (stdio transport) as primary with Stagehand v3 fallback for Shadow DOM extraction failures. Persistent browser profiles in Docker volumes for Salesforce session management.

**Job Queue**: pg-boss v10 with queue-per-stage pattern (scrape-module, extract-content, identify-concepts, chunk-content, generate-embeddings, build-relationships, answer-quiz), priority ordering, dead letter queues, stage-specific retry configuration.

**AI Agents**: Four specialized agents (Scraper, Knowledge, Quiz, Documentation) using Vercel AI SDK v5 with Anthropic provider. Model tiering: Haiku for bulk operations, Sonnet for reasoning. YAML-driven prompts in apps/api/src/prompts/.

**Real-Time**: Dual Supabase Realtime patterns — Pattern A (router.refresh for status changes), Pattern B (useState for live agent logs).

## Technology Stack Quick Reference

- Frontend: Next.js 15 (App Router, RSC) + Tailwind v4 (CSS-first) + shadcn/ui (new-york)
- Backend: Fastify 5 (ESM) + pg-boss 10
- Database: Supabase (PostgreSQL + pgvector + Realtime)
- AI: Vercel AI SDK v5 + Anthropic provider v2
- Browser: Playwright MCP (stdio transport) + Stagehand v3 (fallback)
- Language: TypeScript 5.7 strict, ESM everywhere, no `any`
- Tests: Vitest (unit/integration, co-located), Playwright (E2E)
- Build: Turborepo + pnpm workspaces
